purpose
  The task is where every other class comes together. Kafka Connect runs it as the worker of the connector. It starts the LTL server so that RepAgent can connect, feeds the commands RepAgent sends into the transaction buffer, queues every committed transaction, turns the rows of queued transactions into Kafka records when Connect asks for them (poll), and passes Kafka's confirmations to the acknowledgement tracker, whose position is what RepAgent is told it may free. The delivery guarantee of the connector, at least once, is decided here.

class: SybaseCdcSourceTask
  A subclass of Kafka Connect's SourceTask. Connect creates it, calls start once, then calls poll in a loop, calls commitRecord for every record Kafka confirms, and calls stop at the end. It holds the pieces of the pipeline as fields: the configuration, the mapper, the buffer, the queue, the acknowledgement tracker and the server.

class: SybaseCdcSourceTask.Batch
  A record for one queued transaction: the committed transaction, the rows that will be published (after the table filter) and the handle for the acknowledgement tracker.

class: SybaseCdcSourceTask.TrackedRecord
  A SourceRecord that remembers which transaction it belongs to. Connect hands the same object back in commitRecord, which is how a confirmation can be counted against the right transaction. It builds a record without schemas: the key and the value are plain maps, and the JSON converter of the connector configuration turns them into JSON.

class: SybaseCdcSourceTask.Listener
  The task's answer to the LTL server's questions. It is an inner class so it can use the task's fields. The six methods are the ones of LtlListener.

method: SybaseCdcSourceTask.<init>()
  The implicit constructor. Connect creates the task with it and then calls start.

method: SybaseCdcSourceTask.version()
  Returns the connector's version (0.1.0), which Connect prints in its log when it creates the task.

method: SybaseCdcSourceTask.start(Map)
  Builds everything. It reads and validates the configuration, sets up the mapper, the buffer and the bounded queue, asks Connect for the offset it stored last time and turns it into the starting position, creates the acknowledgement tracker with that position, logs "Starting Sybase CDC task ..." (you saw the line in lesson 6.3) and starts the LTL server. If the port cannot be opened, it throws a ConnectException and the task fails visibly.

method: SybaseCdcSourceTask.poll()
  Called by Connect over and over. It waits up to one second for a queued transaction and returns null if there is none (Connect then simply calls again). Otherwise it turns the rows of that transaction, and of further queued ones up to the configured limit, into records. Each record carries the offset to store if it is acknowledged: only the last record of a transaction carries the position of that transaction's commit; the others carry the previous safe position, so a crash in the middle of a transaction repeats the whole transaction and never loses part of it.

method: SybaseCdcSourceTask.commitRecord(SourceRecord,RecordMetadata)
  Called by Connect when Kafka has acknowledged a record. If it is one of our tracked records, the acknowledgement tracker is told, which may move the safe position forward.

method: SybaseCdcSourceTask.stop()
  Closes the LTL server, which also closes the RepAgent connection.

method: SybaseCdcSourceTask.Batch.<init>(CommittedTransaction,List,AckTracker.Pending)
  The canonical constructor of the record; it stores the three fields.

method: SybaseCdcSourceTask.Batch.equals(Object)
  Generated by the compiler for the record. The task does not rely on it.

method: SybaseCdcSourceTask.Batch.hashCode()
  Generated by the compiler for the record. The task does not rely on it.

method: SybaseCdcSourceTask.Batch.pending()
  Accessor generated for the record component pending.

method: SybaseCdcSourceTask.Batch.rows()
  Accessor generated for the record component rows.

method: SybaseCdcSourceTask.Batch.toString()
  Generated by the compiler for the record.

method: SybaseCdcSourceTask.Batch.tx()
  Accessor generated for the record component tx.

method: SybaseCdcSourceTask.TrackedRecord.<init>(Map,Map,String,Object,Object,AckTracker.Pending)
  Creates the Connect record with the partition, the offset, the topic, the key and the value (and no schemas), and remembers the pending handle.

method: SybaseCdcSourceTask.Listener.<init>(SybaseCdcSourceTask)
  The constructor of the inner class; the outer task is passed in implicitly.

method: SybaseCdcSourceTask.Listener.authenticate(String,String)
  Compares the login RepAgent sent with the configured user and password. Both must match.

method: SybaseCdcSourceTask.Listener.onConnectSource(String,String,int)
  Called when RepAgent says which database it replicates. A different database is refused with an exception. A different server name only produces a warning. A version below 760 is refused. Otherwise the transaction buffer is cleared (RepAgent sends everything again from the truncation point after every connect) and version 760 is agreed.

method: SybaseCdcSourceTask.Listener.maintenanceUser(String,String)
  Returns the configured maintenance user, the database login whose transactions RepAgent does not forward.

method: SybaseCdcSourceTask.Listener.onCommands(List)
  The core of the pipeline. Every command goes into the transaction buffer; when a commit comes out, a transaction whose commit position is not newer than the last one queued is skipped as a repeat of something already published. Otherwise the rows are filtered by the table list, the transaction is registered with the tracker in commit order (transactions without rows still move the position), and a batch is put on the queue. The put waits when the queue is full, which slows RepAgent down while Kafka lags.

method: SybaseCdcSourceTask.Listener.onDisconnect(String,String,Exception)
  Clears the transaction buffer, because the half-finished transactions are sent again after a reconnect, and logs the disconnect.

method: SybaseCdcSourceTask.Listener.truncationPoint(String,String)
  The answer to RepAgent's "get truncation": the position of the latest transaction that Kafka has fully acknowledged, padded to the 36 bytes RepAgent expects. This is the moment the database is allowed to free its log.

lines: 30-38
  The whole pipeline as one picture, plus the delivery rule in words: at least once, the log is released only up to what Kafka acknowledged, and after a restart transactions that were already published are skipped by their commit position.

lines: 53-56
  Two fields that carry the duplicate protection: lastQueued is the newest commit position handed to the queue (older re-sends are duplicates), publishedOqid is the position of the last transaction handed to Connect in poll.

lines: 85-89
  The restart position. Connect's offset reader returns what was stored for this database; its position is passed to the tracker, to the duplicate check and to poll. A first start has none.

lines: 109-121
  The offset rule for a transaction's records: only the last record may say the transaction is done. The comment explains the reason: after a partial publish, a crash repeats the whole transaction and loses nothing.

lines: 176-179
  The duplicate check. A commit that is not newer than the last queued one has already been published before the restart, so it is skipped.

lines: 180-185
  The table filter, the registration with the tracker and the bounded queue. A transaction that has no rows left after the filter still moves the position, so the log can be released.

design
  The queue between the RepAgent thread and Connect's poll thread is bounded. When Kafka is slow the queue fills, the RepAgent thread blocks in the put, the connector stops reading and RepAgent slows down: the pressure travels back to the database instead of piling up in memory.

fits
  SybaseCdcSourceTask is created by SybaseCdcSourceConnector. It reads SybaseCdcConfig, starts an LtlServer, implements LtlListener in its inner Listener class, feeds LtlCommand objects to the TransactionBuffer, uses ChangeEventMapper to build every key, value and topic, uses AckTracker for the safe position and Oqid for positions. CommittedTransaction is what the buffer hands over at commit.
