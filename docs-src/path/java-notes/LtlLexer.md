purpose
  LTL is mostly readable text, but its values are length-prefixed: a value is written as a marker character, a length and then that many bytes. So the message cannot be split at spaces. LtlLexer is the tokenizer: it walks the raw bytes of one message and produces a list of tokens (plain words, the symbols comma, equals and dot, values, and column names) for the parser to read.

class: LtlLexer
  A final class of static methods with a private constructor: it is a function, not an object. It works on bytes, not text, because the lengths count bytes and the values may be in a character set the connector has not decoded yet.

class: LtlLexer.Type
  The four kinds of token. BARE is a plain word or number such as distribute or 255; SYM is one of the three symbols; VALUE is a length-prefixed literal; NAME is a column name inside a "yielding" list.

class: LtlLexer.Token
  One token: its type, a marker character (the datatype marker of a value, the column flag of a name, or the symbol itself), its bytes and its position in the message.

method: LtlLexer.<init>()
  Private and empty: nobody creates a LtlLexer.

method: LtlLexer.expectsName(List,boolean)
  Decides whether the next "~" token is a column name rather than a value. Names appear only inside a yielding list, right after the word before or after, or after a comma. Getting this wrong would read a name as a value, so the rule is kept in one small method.

method: LtlLexer.lengthDigits(char)
  How many base-64 digits make up the length after a given marker. Most types use one digit; the markers of character and binary types switch to two or three digits as the value gets longer.

method: LtlLexer.tokenize(byte[])
  The tokenizer. It skips white space, turns the three symbols into SYM tokens, reads each "~" token as a name or a length-prefixed value, and reads everything else up to the next separator as a bare word. It throws IllegalArgumentException when a token is cut off or a length digit is not valid.

method: LtlLexer.Token.<init>(LtlLexer.Type,char,byte[],int)
  The canonical constructor of the record: it stores the four fields.

method: LtlLexer.Token.data()
  Accessor generated for the record component data: the bytes of the token.

method: LtlLexer.Token.equals(Object)
  Generated by the compiler for the record. The connector does not rely on it.

method: LtlLexer.Token.hashCode()
  Generated by the compiler for the record. The connector does not rely on it.

method: LtlLexer.Token.isBare(String)
  True when the token is a bare word equal to the given word, ignoring case. The parser uses it to recognise keywords such as distribute, begin and yielding.

method: LtlLexer.Token.isSym(char)
  True when the token is the given symbol.

method: LtlLexer.Token.marker()
  Accessor generated for the record component marker.

method: LtlLexer.Token.pos()
  Accessor generated for the record component pos: where the token starts in the message, used in error messages.

method: LtlLexer.Token.text(Charset)
  The token's bytes decoded as text with the character set the caller chooses.

method: LtlLexer.Token.toString()
  A short readable form for error messages: the type, the marker, the first 40 characters of the data and the position.

method: LtlLexer.Token.type()
  Accessor generated for the record component type.

method: LtlLexer.Type.<init>()
  The constructor the compiler generates for the enum.

method: LtlLexer.Type.valueOf(String)
  Generated by the compiler for every enum.

method: LtlLexer.Type.values()
  Generated by the compiler for every enum.

lines: 19-22
  How lengths are written: base-64 digits that start at the character `!` (0x21), so `(` means 7 and `"!` means 64. Lengths count bytes, which is the reason the lexer reads bytes.

lines: 56-62
  The table of markers and their number of length digits. It is learned from real captures of RepAgent traffic, not from a specification.

lines: 76-100
  The "~" branch is the heart of the lexer: first it decides whether this is a column name (and if so reads the flag, the length and the name up to the "=" sign), otherwise it reads the length digits and then exactly that many bytes as the value. A value that would run past the end of the message is an error, never a guess.

lines: 101-111
  A bare word ends at white space, a comma, an equals sign or a tilde. A dot ends it too, except between two digits, so that a number like 12.5 stays one word. The words yielding and distribute switch the "inside a yielding list" flag that the name rule needs.

design
  The lexer decides nothing about meaning. It only cuts bytes into tokens, so that the parser can be written as a simple walk over a list and each side can be tested alone.

fits
  LtlParser calls tokenize on each message and walks the tokens it returns. LtlValues turns the VALUE tokens into Java values. Nothing else reads LTL bytes.
