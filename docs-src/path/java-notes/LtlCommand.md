purpose
  RepAgent describes each change in LTL, a text-like language with one "distribute" command per step of a transaction. LtlCommand is the parsed form of one such command: what kind of step it is (begin, commit, rollback, insert, update, delete), where in the log it happened, which table and which row values it carries. Everything after the parser works with LtlCommand and never sees the LTL text again.

class: LtlCommand
  A Java record, so it is a plain immutable bundle of the fields below with no behaviour except isRowChange(). The parser creates it, the transaction buffer groups it, and the event mapper reads it.

class: LtlCommand.Kind
  The kind of step: BEGIN and COMMIT or ROLLBACK frame a transaction, INSERT, UPDATE and DELETE are the row changes, and OTHER is anything else RepAgent sends (it is kept so nothing is silently dropped).

method: LtlCommand.<init>(LtlCommand.Kind,String,byte[],byte[],String,String,Map,Map,List,String,String,String)
  The canonical constructor of the record. Its parameters are the fields: kind, originTime (when the transaction began at the origin), oqid (the 32-byte position of the log record, strictly increasing), tranId (the transaction id), owner and table, the before and after images of the row, keyColumns (the columns RepAgent flags as primary key), tranName, user (the database user who made the change) and raw (the command text, kept for diagnostics).

method: LtlCommand.after()
  The row after the change, as a map of column name to value; null for a delete. For an update it is already merged with the before image, so it is the full new row, not only the changed columns.

method: LtlCommand.before()
  The row before the change; null for an insert. For an update RepAgent sends all columns before and only the changed columns after, which is why the parser merges them.

method: LtlCommand.equals(Object)
  Generated by the compiler for the record. The connector does not rely on it.

method: LtlCommand.hashCode()
  Generated by the compiler for the record. The connector does not rely on it.

method: LtlCommand.isRowChange()
  The one method written by hand: true for INSERT, UPDATE and DELETE. The transaction buffer uses it to tell the rows it must keep from the begin and commit markers.

method: LtlCommand.keyColumns()
  Accessor generated for the record component keyColumns: the primary key column names. They become the Kafka message key.

method: LtlCommand.kind()
  Accessor generated for the record component kind.

method: LtlCommand.oqid()
  Accessor generated for the record component oqid: the position of this command in the database log. It is what the connector stores as its restart position and what it hands back to RepAgent.

method: LtlCommand.originTime()
  Accessor generated for the record component originTime.

method: LtlCommand.owner()
  Accessor generated for the record component owner: the table owner (dbo in the lab).

method: LtlCommand.raw()
  Accessor generated for the record component raw.

method: LtlCommand.table()
  Accessor generated for the record component table.

method: LtlCommand.toString()
  Generated by the compiler for the record. It prints every field, so it is used mainly when debugging.

method: LtlCommand.tranId()
  Accessor generated for the record component tranId: all commands of one transaction share it, which is how interleaved transactions are told apart.

method: LtlCommand.tranName()
  Accessor generated for the record component tranName.

method: LtlCommand.user()
  Accessor generated for the record component user.

method: LtlCommand.Kind.<init>()
  The constructor the compiler generates for the enum. It is never called directly.

method: LtlCommand.Kind.valueOf(String)
  Generated by the compiler for every enum: looks a constant up by its name.

method: LtlCommand.Kind.values()
  Generated by the compiler for every enum: returns all constants in order.

lines: 9-15
  Examples of the LTL text a command is parsed from (the begin, insert, update, delete and commit forms). The funny characters (`~*6`, `~"(`) are length markers explained in the lexer lesson. Note that an update carries every column before and only the changed columns after.

lines: 17-18
  Two facts that the rest of the pipeline relies on: after is already the full new row for an update, and the key columns are the ones RepAgent flagged.

design
  A record of plain fields, without any Kafka types, keeps the LTL side of the connector independent of Kafka Connect. The same commands could feed another sink, and the parser can be tested without Kafka.

fits
  LtlParser creates one LtlCommand for every distribute command it reads. TransactionBuffer collects them per transaction and hands them over at commit inside a CommittedTransaction. ChangeEventMapper reads the fields of each row change to build the Kafka key, value and topic. LtlListener passes lists of them from the session to the task.
