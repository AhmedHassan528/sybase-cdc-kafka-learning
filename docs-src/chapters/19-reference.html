Glossary

ASE (Adaptive Server Enterprise)
SAP's relational database server, formerly Sybase ASE. Hosts the Phoenix database.
Acknowledgement (Kafka)
The broker's confirmation that a record is stored (with acks=all: replicated to the in-sync replicas). Triggers commitRecord() in the task.
CDC (change data capture)
Publishing every committed insert, update and delete of a database as events, here by reading the transaction log through RepAgent.
Commit OQID
The OQID of a transaction's COMMIT record. Stored as the connector's source offset and returned to RepAgent as the truncation position.
Kafka Connect
Kafka's framework for running source and sink connectors; provides offsets, REST management and restarts.
Interfaces file
Sybase's name-to-address file ($SYBASE/interfaces, sql.ini on Windows). Entry CDC_RS points RepAgent at the connector.
LTL (Log Transfer Language)
The command language RepAgent uses to send log records to a Replication Server (distribute, begin transaction, applied, commit…). SAP documents it up to version 700; this project uses 760, learned from captures.
Maintenance user
The login a Replication Server uses to apply changes; RepAgent does not forward its transactions (prevents loops). Here cdc_maint, never used to write.
Source offset
Kafka Connect's stored position of a source connector, per source partition. Here {database, server} → {commit_oqid}.
OQID (origin queue ID)
A 32-byte, monotonically increasing identifier RepAgent assigns to each log record it sends; sent as a 36-byte locator in get truncation. Used for ordering, duplicate detection (source.oqid) and restart position.
RepAgent (Replication Agent)
A thread inside ASE that reads a database's transaction log and pushes it as LTL over TDS to a Replication Server, here to the connector.
Replication Server
SAP's product that receives LTL from RepAgents and replicates to other databases. The connector impersonates one.
Secondary truncation point
A marker in the ASE log, created when RepAgent is enabled, that prevents log truncation beyond what RepAgent has delivered and had acknowledged. Visible in master..syslogshold.
TDS (Tabular Data Stream)
Sybase/SAP's client–server wire protocol, version 5.0. RepAgent logs in and sends LTL in TDS language packets.
Threshold (ASE)
A free-space level on a segment that runs a stored procedure when crossed. Here sp_cdc_log_alert at 24,576 free log pages.
tran_id / xid
RepAgent's transaction identifier; published as source.xid; all rows of one transaction share it.
Watermark
The newest commit OQID whose transaction and all earlier ones are fully acknowledged by Kafka (AckTracker).

  3. Qlik, Replicate: SAP Sybase ASE prerequisites, "Prerequisites when using RepAgent CDC": help.qlik.com. States that net password encryption must be false "as encrypted passwords are not supported" and shows an interfaces entry pointing RepAgent at Replicate's listener: the same mechanism as this connector.

Source of the KafkaConnect/KafkaConnector CRs (eventstreams.ibm.com/v1beta2), the base image cp.icr.io/cp/ibm-eventstreams-kafka:<version> with plugins in /opt/kafka/plugins/ and USER 1001, and the page banner stating that Event Streams and Event Processing are deprecated with no enhancements, support and security fixes continuing under the support lifecycle.
  5. Linux kernel commit 9fccc5c0c99f, x86/elf: Disable automatic READ_IMPLIES_EXEC on 64-bit: git.kernel.org. Cause of the ASE boot crash on new kernels.
  6. Docker, Seccomp security profiles for Docker: docs.docker.com. Why personality() is restricted by default.
  7. Apache Kafka 3.8 API, SourceTask: javadoc.
  8. Apache Kafka, KIP-618: Exactly-Once Support for Source Connectors: cwiki.apache.org.

  10. Docker Hub images: datagrip/sybase, apache/kafka.

Reproducibility checklist and acceptance status

Reproducibility checklist

  • ☐ Docker installed; 6 GB RAM and ~10 GB disk free for Docker
  • ☐ Project folder complete (inventory); JAR SHA-256 matches or a new build recorded
  • ☐ docker compose up -d; ASE log shows READY
  • ☐ Plugin listed; connector created; task RUNNING
  • ☐ retry timeout 10; sp_start_rep_agent; RepAgent connected … using 760
  • ☐ T1–T3 reproduce (insert/update/delete, rollback, multi-row)
  • ☐ Offsets advance in _connect-offsets; truncation page advances
  • ☐ Optional: T4–T7 with captures/ scripts, checking the database state before each destructive test
