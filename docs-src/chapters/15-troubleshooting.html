Slow delivery

  • Compare ASE commit time with Kafka arrival (test 6 method). In this project the RepAgent log scan was the bottleneck (ASE committed in 25 s, delivery took 122 s).
  • RepAgent tuning parameters exist (scan batch size, ltl batch size, send buffer size); none was changed or tested here. Change one at a time in a test environment.
  • Connect side: CPU of the worker, producer batching, Kafka replication latency (production RF 3 adds latency not present locally).

What to collect before asking for help

  1. Connector status JSON (task trace included).
  2. Worker log around the time, filtered: grep -E "sybase-cdc|ERROR|WARN".
  3. ASE errorlog lines containing RepAgent.
  4. sp_help_rep_agent db, 'process' and 'config' output.
  5. Truncation page and the last _connect-offsets record.
  6. Only if needed and approved: a short ltl.trace=true capture. It contains customer data; handle it as production data and delete it afterwards.
