ChangeEventMapper.java

sybase-cdc-connector/src/main/java/com/phoenix/cdc/sybase/connect/ChangeEventMapper.java · 73 lines · every non-blank line is annotated (checked by gen-source.js)

Role: decides what a Kafka record looks like: the topic name, the key (primary key columns) and the value (operation, before/after images, source position). The format is deliberately close to the widely used Debezium envelope (op, before, after, source, ts_ms) so consumers find it familiar, but it is not Debezium-compatible in field names or types.

Known limitations (documented, not fixed): (1) the topic name ignores the table owner, so dbo.payment and other.payment would share a topic; (2) txn_rows counts all rows of the transaction, including rows of tables excluded by table.include.list; (3) the output is schemaless JSON, so Avro/Schema Registry is not supported yet.

Lines 38–44

Key: a map of the primary-key columns (flag G in LTL) taken from the after image, or the before image for deletes. Tables without a primary key get a null key, so their events are spread round-robin across partitions and lose per-row ordering when a topic has more than one partition. A primary key on every captured table is a prerequisite for ordering guarantees.

The source block: where the change came from and its exact log position. oqid is unique per row change and increases in log order, which makes it the de-duplication key for consumers. commit_oqid is shared by all rows of a transaction. seq is the row's index inside the published rows of the transaction; txn_rows is the transaction's total row count. Numbers are cast to long because the schemaless JsonConverter needs standard Java types.
