LtlListener.java

sybase-cdc-connector/src/main/java/com/phoenix/cdc/sybase/ltl/LtlListener.java · 32 lines · every non-blank line is annotated (checked by gen-source.js)

Role: the contract between the protocol layer (LtlSession, which speaks TDS/LTL to RepAgent) and whoever owns it. Two implementations exist: the inner class Listener in SybaseCdcSourceTask (production) and an anonymous class in LtlProbe (discovery tool, no Kafka). This separation is why the protocol code could be developed and debugged against the real RepAgent before any Kafka code existed.

Threading: every method is called on the RepAgent session thread, never on the Kafka Connect task thread.

What: a Java interface, a set of method signatures without (most) bodies. A class that writes implements LtlListener must provide them. Why: dependency inversion: LtlSession depends on this small interface, not on Kafka Connect classes, so the protocol layer has no Kafka dependency and can run inside the probe.

Called once per connection with the user and password from the TDS login record. Returning false makes the session send "Login failed" (Msg 4002), which RepAgent logs and then stops its thread. Important: the password is only readable because the DBA set net password encryption to false; with encryption on, RepAgent leaves the password field empty (seen in capture 1).

17    /** Login of the maintenance user; RepAgent does not forward that user's transactions. */
18    String maintenanceUser(String server, String database);
Lines 17–18

Answer to get maintenance user. RepAgent does not forward transactions executed by this login (that is how Replication Server avoids replicating its own applied changes back). The connector returns a login that should never run business transactions (cdc_maint by default). Risk: if this returned the login used by Phoenix, its changes would be filtered out.

The most safety-critical method: the 36-byte value RepAgent uses to move the database's secondary truncation point. Returning a position the connector has not safely stored in Kafka would let ASE discard log records that were never delivered. The production implementation returns the AckTracker watermark.

Lines 27–28

Receives each parsed LTL batch in log order. throws InterruptedException allows the implementation to block (the production task blocks on a bounded queue), which simply stops reading from RepAgent: natural back-pressure, because RepAgent waits for the DONE reply before sending more.
