Oqid.java

sybase-cdc-connector/src/main/java/com/phoenix/cdc/sybase/cdc/Oqid.java · 34 lines · every non-blank line is annotated (checked by gen-source.js)

Role: small static helpers for the origin queue ID (OQID), the 32-byte position RepAgent attaches to every LTL command. Everything that decides "is this before or after that?" in the connector goes through compare(); everything sent back to RepAgent goes through locator().

Used by: SybaseCdcSourceTask (dedupe, offsets, truncation), ChangeEventMapper, LtlProbe. Version-sensitive: yes, the 36-byte locator length and the OQID byte layout come from the SAP LTL documentation (RS 15.0.1 Design Guide) and were confirmed by capture on ASE 16.0 SP02; re-check on SP04.

17    /** Unsigned byte-wise comparison: OQIDs increase in log order. */
18    public static int compare(byte[] a, byte[] b) {
19        return Arrays.compareUnsigned(a, b);
20    }
Lines 17–20

What: compares two OQIDs byte by byte as unsigned numbers (0–255), returning negative, zero or positive like any Java comparator. Why unsigned: Java's byte is signed (-128..127). Byte 0x9f would compare as negative and sort before 0x10, breaking log order. Arrays.compareUnsigned (Java 9+) fixes this. Why it matters: the duplicate filter in the task skips any transaction whose commit OQID is not greater than the last one queued. A wrong comparison would silently drop or duplicate transactions. Assumption: OQIDs increase in log order (stated by SAP, observed in every capture). After a database load/restore the generation number in bytes 0–1 changes; see the version chapter.

22    /** The value returned to "get truncation": the OQID padded to 36 bytes, or zeros if none. */
23    public static byte[] locator(byte[] oqid) {
24        return oqid == null ? new byte[LOCATOR_LEN] : Arrays.copyOf(oqid, LOCATOR_LEN);
25    }
Lines 22–25

What: builds the answer to RepAgent's get truncation: the OQID copied into a 36-byte array (padded with zeros), or 36 zero bytes when nothing has been acknowledged yet. Arrays.copyOf(src, 36) creates a new array, copying the 32 bytes and zero-filling the rest. Verified: zeros on first start are accepted (tests 1–7 all began that way). An earlier experiment that returned a zero-length value was reverted; see the 4047 incident. If changed: returning an OQID that is not yet in Kafka would let ASE free log that has not been delivered (data loss on a crash).

Bytes → lowercase hex text (e.g. 000000000000144a...), or null for null. Used for logs, Connect offsets (JSON cannot hold raw bytes) and the event's source fields. The ternary operator cond ? a : b avoids a NullPointerException.

31    public static byte[] fromHex(String h) {
32        return h == null || h.isEmpty() ? null : HexFormat.of().parseHex(h);
33    }
Lines 31–33

Hex text → bytes, the reverse of hex(). Returns null for null or an empty string, which is how the task reads "no stored offset" (the first records of the very first transaction carry an empty offset; see SybaseCdcSourceTask.poll()). parseHex throws IllegalArgumentException on invalid text; a corrupted offset therefore fails the task at start instead of starting from a wrong position.
