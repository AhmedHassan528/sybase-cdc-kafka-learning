TransactionBuffer.java

sybase-cdc-connector/src/main/java/com/phoenix/cdc/sybase/cdc/TransactionBuffer.java · 84 lines · every non-blank line is annotated (checked by gen-source.js)

Role: implements the rule "publish only on COMMIT, discard on ROLLBACK". RepAgent sends log records in log order, and the log interleaves many concurrent transactions. The buffer keeps a list of row changes per transaction id and releases the list as a CommittedTransaction when that transaction's COMMIT arrives.

Thread: only the RepAgent session thread uses it (not thread-safe by design). Memory: all rows of an open transaction are held in memory; a very large transaction (the 200,000-row test 6b) is held completely. Tests: TransactionBufferTest, scenarios 2, 3, 6b.

COMMIT: remove the buffer and return everything as a CommittedTransaction, with the COMMIT record's OQID as the transaction's log position and its origin time as the commit time. A COMMIT with no buffered rows returns a transaction with an empty list; the task still registers it so the truncation point can advance (see AckTracker). ASE's own system transactions (e.g. rs_logexec, _dmpxact) arrive this way.
